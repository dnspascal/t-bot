Part 3 — Onboarding XRPUSD: one blocker found and fixed, one still open
Market-hours logic made symbol-aware (shipped); real symbol ID still needed (open)
Weekend-close and EOD-window logic was provider-aware only, not symbol-aware Fixed and shipped

weekendPositionCloser (fires Friday 21:30 UTC) and isEODWindow (blocks new entries and force-closes daily at 21:30 UTC on weekdays) were both gated only on provider.Name() == "ctrader" — correct for EURUSD/XAUUSD, wrong for any continuously-trading instrument on the same provider. Crypto spot/CFDs trade through weekends and don't have a dead session. Added a continuousTradingSymbols lookup (internal/bot/watcher.go) keyed on the already-available b.symbol field — no constructor changes needed. isEODWindow converted from a bare function to a *Bot method so it can check this per-instance. Default behavior for every symbol not explicitly listed is unchanged — EURUSD/XAUUSD keep the exact same weekend/EOD handling as before this change.

Real XRPUSD symbol ID still unknown — the by-ID name decoder is unreliable, don't trust it Open

Built queries/ctrader_symbol_list (2026-08-26) to query cTrader's by-ID symbol lookup in bulk. Confirmed live and useful for ID→raw-response round trips, but the name-reconstruction logic (decodeFullSymbol in the vendored provider client, fields 23/40 guessed as quote/base asset) is wrong: id=41, independently confirmed as XAUUSD from the bot's own live spot-event logs, decodes to "OzUSD" through this path. Scanned ids 1-400 (69 real entries returned) with no correctly-labeled XRPUSD match, but that result can't be trusted given the decoder bug — a real entry could be present under a garbled name. Decided against further live-connection guessing to fix the decoder; the practical unblock is checking the symbol ID directly in the Pepperstone platform UI. Once the real ID is known, remaining steps are pip size, lot/volume convention, instances/xrpusd.env, and adding xrpusd to deploy.yml's TBOT_SYMBOLS — all straightforward given the templated infra from Part 1.

Also still open, unrelated to the ID: no strategy tuning from 2026-08-26 (freshness gates, watcher fixes, breakeven timing) has been validated against crypto price behavior. Recommend treating XRPUSD as observation-only for a period once live, before trusting any of today's strategy-level fixes to transfer.
