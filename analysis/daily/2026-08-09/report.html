01 — Key Findings
What we found this week
dd_ranging_breakout — firing every 5–20 min, mostly hitting SL
Critical

Strategy was entering on every M5 breakout signal with no regard for whether the breakout had real momentum behind it. M15 ADX was 10–19 on every single losing trade.

An earlier attempt to fix this with an M15 EMA bullish check was ruled out — confirmed by data that M15 EMA was bullish all week, so it would have blocked nothing. ADX was the real differentiator.

  • Winning trades (05:55 +$8.67, 06:00 +$1.69): M15 ADX 21–24
  • All losing trades: M15 ADX 10–19
  • M15 EMA: bullish all week — would have filtered zero trades
trend_follow — trades going right, still losing to SL
Significant

TP on XAUUSD trend_follow was ~$27. minPeakGain = tpDist × 0.5 means peak_drawback only arms after $13.50 favorable. Several trades peaked at $8–$15 then reversed all the way to SL — zero protection in that zone.

Fix: broker SL amendment to break-even when position reaches 40% of TP distance favorable. Buffer = 2 pips above open (covers broker commission ~$0.08/trade).

  • Multiple positions: max_favorable $8–$15, closed at full SL loss
  • Break-even at 40% of TP dist would have saved most of these
  • peak_drawback (60%) still arms independently — both protections coexist
Regime classification weakness — ADX ignored in trend detection
Architecture

trending_up / trending_down is classified by EMA gap ≥ 0.1% alone. ADX is not checked at all. This means trend_follow can fire on drifts that technically have a bullish EMA gap but no directional conviction.

Added H1 ADX ≥ 20 filter inside trend_follow. trend_follow was the week’s top earner (+$204) specifically on high-ADX days — the filter preserves those while blocking weak-drift entries.

Positions with peak favorable/adverse — break-even damage analysis
sql
SELECT
  p.provider_position_id,
  sig.strategy_name,
  p.side,
  p.open_price,
  p.max_favorable,
  p.max_adverse,
  f.gross_profit,
  f.commission,
  CASE
    WHEN p.side = 'BUY'  THEN p.max_favorable - p.open_price
    ELSE                       p.open_price - p.max_favorable
  END AS peak_gain,
  CASE
    WHEN p.side = 'BUY'
      THEN (p.max_favorable - p.open_price) / NULLIF(p.tp_price - p.open_price, 0) * 100
    ELSE (p.open_price - p.max_favorable) / NULLIF(p.open_price - p.tp_price, 0) * 100
  END AS peak_as_pct_of_tp_dist
FROM positions p
JOIN orders o    ON o.id = p.our_order_id
JOIN signals sig ON sig.id = o.signal_id
JOIN fills f     ON f.position_id = p.id AND f.is_close = true
WHERE p.created_at >= '2026-08-03'
  AND p.created_at <  '2026-08-08'
  AND p.provider = 'ctrader'
  AND f.gross_profit < 0
ORDER BY peak_gain DESC;

Added encodeAmendPositionSLTPReq. Field numbers match proto spec: 1=payloadType, 2=accountID, 3=positionId, 4=stopLoss. Does not call encodeEnvelope — SendRaw handles the outer envelope.

func encodeAmendPositionSLTPReq(accountID, positionID int64, newSL float64) []byte {
    var b []byte
    b = appendUint32(b, 1, ProtoOAAmendPositionSLTPReq)
    b = appendInt64(b,  2, accountID)
    b = appendInt64(b,  3, positionID)
    b = appendDouble(b, 4, newSL)
    return b
}
Bug caught: Original version called encodeEnvelope itself (double-wrapping) and used wrong field numbers 1/2/3 for data fields instead of 2/3/4.

func (b *Bot) checkBreakEven(ctx context.Context, pos trackedPosition) {
    if pos.BreakEvenActive { return }
    slDist := pos.OpenPrice - pos.SLPrice
    if pos.Side == config.SignalSell { slDist = pos.SLPrice - pos.OpenPrice }
    if slDist <= 0 { return }
    // peakGain = favorable movement from open price
    if peakGain < 0.40*slDist { return }
    // newSL = open + 2 pips (BUY) / open - 2 pips (SELL)
    b.provider.AmendPositionSL(ctx, pos.ProviderPositionID, newSL)
    b.registry.SetBreakEven(pos.ProviderPositionID)
    // INSERT position_adjustments (old_sl, new_sl, "break_even")
}
Why broker amendment not internal close: Crash-safe — SL lives at the broker on restart. position_adjustments table was built for this. Why 40%: covers the unprotected zone below minPeakGain = tpDist × 0.5.

04 — Break-Even Flow
End-to-end execution path
execution path
price tick
  └─ checkPeakDrawback()
       ├─ UpdatePeaks()
       ├─ checkBreakEven()
       │    peakGain ≥ 40% of TP dist?
       │    ├─ yes → AmendPositionSL  (ProtoOAAmendPositionSLTPReq 2110)
       │    │         └─ SendRaw → encodeEnvelope → TCP frame
       │    │              broker responds → ExecutionEvent (2126)
       │    │                               ORDER_REPLACED (4)
       │    │                               → onExecution logs confirmation
       │    │         SetBreakEven (BreakEvenActive = true)
       │    │         INSERT position_adjustments (old_sl, new_sl, "break_even")
       │    └─ no  → skip
       └─ peakDrawbackPct ≥ 60%?
            ├─ yes → closeTrackedPosition()
            └─ no  → continue
