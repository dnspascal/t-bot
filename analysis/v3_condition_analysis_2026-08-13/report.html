Part 1 — What changed from v2
Fixing the exact blind spot that broke dd_ranging_breakout

v2_condition_analysis_2026-08-04 (the tool that produced dd_ranging_breakout and dd_oversold_bounce) had two structural gaps, found while diagnosing why those strategies were getting stopped out in 9-27 seconds live despite a backtested 60-70% win rate:

Hit-detection used 5-minute bars Fixed in v3

A stop that's 0.5-1.0x ATR sits well inside a single M5 bar's range — the backtest could only see whether a bar's High/Low eventually touched TP or SL, not the order or speed of touches within it. v3 scans M1 candles instead (96,427 rows available across the full history), giving real minute-by-minute resolution.

The scan skipped the signal's own bar entirely Fixed in v3

v2's scan started at sc[i].BarTime.After(m.CreatedAt) — strictly after the signal moment, so any reversal in the seconds right after entry was invisible to the backtest. That's exactly where live SL hits were happening. v3 starts at the M1 bar containing the signal moment itself.

Also swept SL multiple (0.5x / 1.0x / 1.5x ATR) instead of hardcoding 0.5x, since that's the exact parameter today's live fix changed — this lets a condition group's robustness across stop width be checked directly, rather than assumed.

Part 2 — The finding
One condition group stood out — and it's robust in a way dd_ranging_breakout never was
H1=ranging, M15=ranging, M5=breakout, M5 EMA=bear, M5 RSI=mid (50–59), M5 ADX=weak (<25), M5 momentum=stable → BUY
n=34, best result across all 474 condition groups tested

1.0x ATR (shipped)34 67.6%79.4%85.3% 85.3%85.3%
1.5x ATR34 67.6%79.4%85.3% 85.3%85.3%

Buy win rate is identical at every SL width tested. Across all 34 real signal moments in this group, the stop-loss is never what decides the outcome — trades resolve via TP or timeout, not via getting stopped out. That's the opposite failure mode from dd_ranging_breakout, where win rate collapsed live because the stop was inside normal noise.

Why a "bear" EMA condition produces a BUY edge

EMA cross is a lagging indicator — it confirms a trend after it's already underway. A bearish EMA cross (fast < slow) combined with an M5 breakout regime, neutral RSI (not yet overbought), and weak ADX (no trend confirmed yet) reads as: price has already started breaking upward, but the lagging EMA hasn't flipped to confirm it. That's an early-entry pattern, not a contrarian one — you're getting in before the crowd's lagging indicators agree with the move.

The honest caveat

n=34 is right at the analysis tool's minimum sample threshold (minN=30). This is real signal — not noise dressed up, since the M1/entry-bar fix means it isn't hiding the same blind spot that broke the last two data-driven strategies — but it's still a small sample. Treat the 85.3% figure as promising, not proven.

Part 3 — What we built
dd_early_breakout — shipped live, not paper mode

internal/strategy/dd_early_breakout/strategy.go encodes the condition group exactly as found. SL set to 1.0x ATR rather than the tightest width tested (0.5x) — the backtest shows this costs nothing (SL isn't the deciding factor either way) while hedging against the sample being smaller than it looks. TP stays at 1.5x ATR, matching the analysis tool's assumption.

    tpATRMult = 1.5

Wired into cmd/bot/bot_init.go's strategy selector — added to both the "all" bundle (what's actually live on gold right now) and the "dd_all" bundle, alongside a standalone STRATEGY=dd_early_breakout option for running it in isolation later if needed.
